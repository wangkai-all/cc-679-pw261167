# RefGap · 跨表引用发现与入仓校验

上传几张表，找出**值域包含**（inclusion dependency / 候选外键）关系，逐条查看
覆盖的真实记录与不能匹配的反例；把确认的关系交给一个**独立**的入仓校验器，
下一批文件出现孤儿记录时拒绝对应发布。

> 这个名字强调「缺口」：候选关系本身来自数据，不来自字段名；发现的是**包含依赖**，
> 不是业务语义。工具不会声称找到了业务中所有外键。

---

## 快速开始

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/python run.py --port 8000
# 打开 http://127.0.0.1:8000
```

页面流程：**创建批次 → 上传文件 → 设参数并搜索 → 逐条审阅证据 → 确认/排除 →
用下一批文件执行入仓校验**。

演示数据在 `samples/`（重新生成：`.venv/bin/python samples/make_samples.py`）：

| 目录 | 用途 |
| --- | --- |
| `samples/data/` | 第一批，用于发现关系 |
| `samples/next/` | 第二批，含孤儿记录，用于演示拒绝发布 |
| `samples/confirmed_relations.json` | 手工示例清单（CLI 校验器可直接用） |

## 具体做什么

### 1. 候选来自包含，不来自名字

对每对表、每个列组合（宽度 1 或 2），检查**子表键集合 ⊆ 父表键集合**。

- 字段值不相交时，无论列名多像，都不会被列为引用。``supplier_items.product_id``
  与 ``legacy_products.product_id`` 同名同类型、值域不相交，结果是结构性排除。
- 列**顺序**参与判断：`(门店, 商品)` 与 `(商品, 门店)` 是两个不同候选。
- 组合键按**元组**编码，每个分量带类型标签和长度信息；`("a|b", "c")` 与
  `("a", "b|c")` 永不碰撞。整数 `1` 与字符串 `"1"` 也不同。
- 支持 CSV / TSV / JSONL / XLSX。数值按 Decimal 规范化比较，`1` 与 `1.0` 在数值
  映射下相等，但 `001` 这类前导零编码保持字符串。

### 2. 空值规则：可选且明确

搜索前必须选择一个，规则同时用于发现和校验，并在确认时写入关系清单：

| 规则 | 含义 |
| --- | --- |
| `skip_child_nulls`（默认） | 子表键含空值的行跳过，不计覆盖也不计违规 |
| `fail_child_nulls` | 子表键含空值的行计为违规（作为孤儿列出） |
| `match_nulls` | 空值等于空值；整键全空的行不计为键 |

界面会显示每种规则下有多少行被跳过或计为违规。

### 3. 父表重复不增加覆盖率

父表值域先去重再比较，因此 3 条重复的 `S01` 只是 1 个键。页面同时显示
**键覆盖率**与**行覆盖率**，并把父表被合并的重复行数单独列出。

### 4. 空表 / 全空列不会被悄悄当成高可信引用

空表、全空列、没有可比较行的候选被归类为**结构性排除**（`child_empty`、
`parent_all_null` 等），在「实际搜索范围」里按原因计数并给出示例，永远不会出现
高置信的「包含」结论。

### 5. 单列包含只是组合的必要条件

两列组合的候选中，先检查每个单列投影。**投影不包含 → 组合必然不包含**，可以
安全剪枝；**投影包含 ≠ 组合包含**，绝不因此删掉二元候选，必须实际核验元组。

页面会明确显示：两个单列都包含、但组合不包含时，该候选仍是「部分包含」并列出
反例。示例 `order_lines[store_id,sku] → store_sku_catalog[store_id,sku]` 正是这种
情况（覆盖率 50%）。

投影检查基于**实际参与比较的键集合**（已按空值规则过滤），因此不会因为被跳过的
空值行而误剪枝。

### 6. 搜索利用统计量缩小候选，再精确核验

分类（可证明的剪枝）与核验（预算内精确扫描）是两件事：

| 剪枝依据 | 说明 |
| --- | --- |
| 类型 | 自动映射只在同一族内放宽（int↔float、date↔datetime），不跨 string/数值 |
| 去重域基数 | 子表去重键多于父表 → 必然不包含 |
| 取值范围 | 任一列的最小/最大值超出父表 → 必然不包含 |
| 单列投影 | 投影不包含 → 组合必然不包含 |
| 空/退化 | 空表、全空列、无可比较行 |

剩下的候选做精确核验：构造父子键集合求差，得到覆盖键数、覆盖行数、缺失键与反例。

**预算**：可设最多核验候选数与时间上限。用尽时页面显示「实际搜索范围」：
枚举多少、结构性排除多少（按原因）、可核验多少、已核验多少、**未核验多少**，
以及「本次结论仅代表该范围」的提示。

### 7. 保存输入、参数、进度，可中断继续

SQLite 中保存：文件内容哈希、解析出的列类型、**完整搜索参数**、每个已完成候选的
结果与反例（反例单独建表，可完整下载）。运行页可「停止」；停止后点「继续未核验的
候选」，已完成的候选不会重算，范围计数把已核验的部分算进去，不会重复计数。

### 8. 下载反例、确认或排除、对比下一批

- 候选页列出覆盖记录和反例（源行号、键值、出现次数、是否空键），可下载 CSV。
- 对「部分包含」的候选点确认时，必须显式勾选「我知道仍存在缺口」。
- 反向决定不会静默覆盖：已确认的候选要改成排除，必须先撤销。
- 入仓校验页会与上一次校验对比：新生成了哪些缺口键、解决了哪些、哪些仍在，
  以及每条关系的孤儿行数变化。

### 9. 只用确认过的关系做入仓约束

「排除」和「未决定」的候选永远不会变成硬约束。校验器只接受
`status: confirmed` 的关系清单（页面可下载 `manifest.json`）。

## 独立入仓校验器

`validator/` 不导入发现模块，也不读它的数据库；它只吃关系清单 + 文件：

```bash
.venv/bin/refgap-validate \
  --manifest samples/confirmed_relations.json \
  --file orders=samples/next/orders.csv \
  --file stores=samples/next/stores.csv \
  --file products=samples/next/products.csv \
  --file inventory_snapshots=samples/next/inventory_snapshots.csv \
  --file store_sku_catalog=samples/next/store_sku_catalog.csv
```

退出码：`0` 允许发布，`1` 存在孤儿/缺失引用（拒绝对应发布），`2` 清单或输入不可读
（含「清单里没有已确认关系」——不会用猜测代替约束）。

「拒绝发布」的原因会分类显示：`N 条已确认引用的子表键在父表中缺失` 是真正的
孤儿；`N 条关系无法结构校验（缺表/缺列）` 是没拿到可核验的父表或列，两者不会
混在一起被误称为「孤儿记录」。若输入文件本身读不出来，CLI 以退出码 `2` 失败，
而不是假装完成了一次校验。

校验器的行为：

- 逐条列出**缺失键**（行号 + 键值 + 出现次数），并给出完整计数。
- 父表缺失或没有可用键、而子表有需要解析的行 → **失败**，不是静默通过。
- 子表缺列 / 本批没有该表 → 标记 `not_applicable` 并说明，绝不静默通过。
- 使用确认时记录的映射与空值规则，比较的正是发现时比较的东西。
- 若某列在本批被解析成不同类型，会给出告警（类型漂移），但仍按确认时的规则核验。

## 参数速查

| 参数 | 说明 |
| --- | --- |
| 组合宽度 | 1 或 2；2 会枚举两列的**有序**组合 |
| 空值规则 | 见上表，默认跳过子表空键 |
| 类型映射 | `auto` / `none`（严格）/ `string` / `number` / `datetime` / `boolean` |
| 候选列 | 每张表可限定参与搜索的列（逗号分隔），会写进运行参数 |
| 最多核验数 / 时间预算 | 超出后报告未核验数量 |
| 自引用 | 默认关闭；开启后同表不同列之间也会搜索（不做同列自反） |

## 结构

```
refgap/
  loader.py    解析文件、推断列类型、统一空值判定
  types.py     类型映射、规范化与带标签的键编码
  domain.py    去重值域、基数、取值范围、空值选择
  search.py    枚举 → 分类剪枝 → 精确核验 → 范围报告
  store.py     SQLite：数据集、运行、候选、反例、决定、校验历史
  gaps.py      两批校验的缺口差异（复用校验器的编码）
  web.py       Flask 页面
validator/
  core.py      独立校验逻辑
  cli.py       入仓门禁 CLI（退出码 0/1/2）
templates/     页面
tests/         规则级测试（见下）
samples/       样例批次与生成脚本
```

## 测试

```bash
.venv/bin/python -m pytest
```

测试按「规则」组织，而不是按函数：

- `test_domain_and_encoding.py`：元组分隔符不碰撞、列顺序、父表重复折叠、映射矩阵
- `test_search_semantics.py`：同名不包含、两单列包含但组合不包含、投影剪枝的正确性、
  空值三规则、空表/全空列、覆盖率的键/行两种口径
- `test_validator.py`：孤儿拦截、排除项不成为约束、缺失父表/子表/列的处置、复合键顺序
- `test_store_and_resume.py`：参数与输入版本持久化、中断继续、预算范围、决定与撤销
- `test_gaps.py`：新增/解决/持续缺口键
- `test_web.py`：上传 → 搜索 → 确认 → 校验的完整路径，反例下载，部分包含确认门槛

## 边界（有意不做的）

- 不识别「业务上应该存在」的关系；只报告数据上成立（或几乎成立）的包含。
- 不自动确认任何候选；不把排除项转成约束。
- 不处理跨文件的主外键命名约定、大小写折叠或隐式单位换算（需要时用显式类型映射
  或先清洗数据）。
- 宽度上限为 2，因为三列以上的组合枚举与审阅成本会迅速失控；需要时可在
  `SearchParams.width_max` 基础上扩展枚举，但应同时扩展预算与 UI。
